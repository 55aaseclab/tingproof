# 一、概述（为什么做）

## 1.1 产品概述及目标

### 1.1.1 背景介绍

用户当前拥有一批长时课堂录音及机器转写，希望通过人工听校得到准确、完整、可读、可追溯的最终文稿。传统做法是在音频播放器、SRT 文件和文本编辑器之间来回切换，主要问题不是“没有编辑器”，而是听音、定位、修改、存疑、复核和成稿彼此脱节：

1. 音频较长，反复拖动播放器难以精确回到同一句。
2. 声音不清楚时，需要降速、回退、循环和增强，但普通播放器操作成本高。
3. 机器字幕会出现错词、断句、标点、专名、水印和漏转；仅通读文字无法发现漏掉的声音。
4. 修改 SRT 容易破坏时间轴，最终书稿又需要重新排段、去口语和组织章节。
5. 对听不清的内容，人容易凭上下文“猜”；若不保留疑点和证据，后续无法可靠复核。
6. 工作跨度长，没有自动保存、进度记录和版本快照时，容易丢改动或重复劳动。
7. 成稿中的结论如果不能回到原音时间点，无法审计其准确性。

本仓库中的真实材料确认了上述问题及规模：

| 项目 | 当前实况 | 对产品设计的影响 |
| --- | --- | --- |
| 音频 | 21 份 MP3，合计 66:08:49.916，约 1.77 GiB | 必须支持批量导入、超长音频、后台索引和断点续做 |
| 单文件 | 抽样文件时长 03:24:50.090，64 kbps、44.1 kHz、单声道；全量中存在 5 小时以上文件 | 波形不能一次性全量渲染；播放和定位必须稳定 |
| 字幕 | 21 份 SRT，共 24,671 个字幕段 | 必须支持大规模分段编辑、搜索、合并与拆分 |
| 文件命名 | MP3 与 SRT 的空格数量不一致，如“青创 一   1 … .mp3”与“青创 一 1 … .srt” | 导入时要规范化文件名并自动配对，冲突时人工确认 |
| 转写质量 | 存在 TurboScribe 水印、错词、跨字幕断句、标点不统一和口语冗余 | 需要规则检查、术语表和原稿/校对稿分层 |
| 覆盖差异 | 音频合计时长比现有 SRT 账本末尾合计多 00:07:08.606 | 不能以“最后一条字幕已改完”代替全音频覆盖验收 |
| 下游用途 | 已有 Markdown 书稿、章节账本及精确来源时间范围 | 成稿必须保留来源文件与毫秒级时间范围，并支持仓库格式导出 |

旧方案是“播放器 + 文本编辑器 + 人脑记进度”。用户已经在实际校稿，需求来源明确，且现有素材足以作为产品验收数据。成功与否不以“用了 AI”衡量，而以校对覆盖率、剩余疑点、可追溯性和人工耗时衡量。

### 1.1.2 产品概述

听校采用“三层文稿、一个证据轴”：

| 层级 | 是否可改 | 作用 | 质量要求 |
| --- | --- | --- | --- |
| 原始识别层 | 否 | 保存导入时的 SRT 原貌，作为机器结果基线 | 字节级保留，可随时对照 |
| 逐字校对层 | 是 | 忠实记录原音，改正错词、断句、标点和说话人；保留有意义的口语信息 | 每一段均绑定原音时间范围和人工状态 |
| 成稿层 | 是 | 在不改变原意的前提下去口语、重组段落、配置标题和章节 | 每一段均能回溯到一个或多个已确认校对片段 |

~~~mermaid
flowchart LR
    A[原始音频：唯一事实来源] --> B[原始识别层：只读]
    A --> C[逐字校对层：忠实听校]
    B --> C
    C --> D[成稿层：可读性编辑]
    C --> E[疑点与术语库]
    E --> C
    D --> F[质量闸门]
    C --> F
    F --> G[SRT / TXT / Markdown / JSON 导出]
~~~

**[假设 A1]** 首个可用版本是安装在个人电脑上的本地桌面应用，默认不上传音频、字幕或文稿。建议先支持当前工作环境 Linux，并保持跨平台实现能力。

**[假设 A2]** 用户需要的不只是修正 SRT，而是同时得到“可核对的逐字校对稿”和“可阅读的最终成稿”；两层必须分开，避免为了行文好看而污染事实记录。

### 1.1.3 产品目标

#### 业务目标

本项目是内部生产力工具，业务目标是把一次性的人工校稿过程沉淀为可重复、可验收的生产流程。

| 目标 | 指标定义 | V1.0 目标值 | 评估方式 |
| --- | --- | --- | --- |
| 完成全量材料校对 | 已通过质量闸门的有效语音时长 ÷ 检出的有效语音总时长 | 100% | 以 21 份音频为首个生产项目 |
| 消除“静默漏稿” | 未处理的“有语音、无文字”候选区间数 | 0 | VAD 候选逐条确认：补录、非语音或可接受缺失 |
| 保证成稿可追溯 | 有有效来源映射的成稿段落数 ÷ 全部成稿段落数 | 100% | 导出前强校验 |
| 控制未决问题 | 阻塞级未解决疑点 | 0 | 质量闸门不允许带阻塞疑点完成 |
| 提升人工效率 | 同一难度样本下，每音频小时的人工校稿耗时 | 相比“播放器 + 文本编辑器”降低至少 30% | 首次用 60 分钟分层抽样建立基线 |
| 防止数据丢失 | 因崩溃导致的已输入内容丢失窗口 | 不超过 5 秒 | 崩溃恢复测试 |

**[待确认 C1]** “效率提升至少 30%”是建议目标；正式基线尚未测量。建议从清晰、一般、困难片段各抽 20 分钟，记录旧流程与听校流程的净操作时间后确认。

#### 用户目标

| 目标用户 | 用户目标 | 衡量指标 |
| --- | --- | --- |
| 主校对者 | 不离开工作台即可听清、修改并确认当前句 | 90% 以上常用操作可由键盘完成；从暂停到重听不超过一次按键 |
| 主校对者 | 随时知道做到哪里、还剩什么 | 文件、时长、字幕段、疑点四种进度均可见 |
| 复核者 | 快速定位疑难处，不重听整份音频 | 点击疑点后 2 秒内开始播放带上下文的原音 |
| 成稿编辑者 | 改写时不丢失原意和出处 | 每个成稿段落可一键回放全部来源范围 |
| 项目负责人 | 只有达到明确质量标准时才宣告完成 | 完成状态由系统质量闸门计算，不能仅手动勾选 |

#### 北极星指标

**已人工确认且可追溯的有效语音分钟数。**

该指标同时要求“听过”“确认过”“能回到原音”，比字数、文件数或打开应用次数更接近真实产出。

#### “完美文稿”的操作性定义

本 PRD 不把“完美”定义为主观的零瑕疵，而定义为以下可验收条件全部成立：

1. 检出的有效语音区间全部被人工覆盖。
2. 逐字校对层无机器水印、无未处理的时间轴错误、无阻塞疑点。
3. 所有无法从原音确定的内容均明确标记，不以猜测冒充原话。
4. 成稿层通过项目风格规则，且每段有来源映射。
5. 导出文件可重新导入，时间轴、文本和状态不丢失。
6. 用户对质量报告签署“完成”。

声音中已经永久缺失的信息无法被软件恢复。因此，“原音确实不可辨”是合法结论；诚实标注比编造一个流畅答案更接近完美。

### 1.1.4 目标用户

| 角色 | 特征 | 当前做法 | 核心诉求 |
| --- | --- | --- | --- |
| 主校对者 | 熟悉中文内容，长时间听写与修订 | 播放器和编辑器来回切换 | 快捷播放、精确定位、无损编辑、不中断心流 |
| 复核者 | 对课程术语、人物或背景更熟悉 | 收到零散问题后单独找音频 | 集中处理疑点、看到上下文、留下结论 |
| 成稿编辑者 | 负责把口语整理成书面稿 | 从 SRT 或片段复制粘贴 | 双栏对照、来源绑定、章节组织、规则检查 |
| 项目负责人 | 关注进度和最终质量 | 人工询问与抽查 | 全局进度、质量闸门、版本与导出记录 |

**[假设 A3]** V1.0 的四个角色由同一名本地用户兼任，不做账号、联网和实时多人协作；仍保留“校对、复核、签署”三类动作记录，便于未来扩展。

## 1.2 名词说明

| 名词 | 说明 |
| --- | --- |
| 原音 | 导入的音频源文件，是判断文字正确性的最终事实来源 |
| 原始识别层 | 导入的 SRT/VTT 等机器识别结果，只读保存 |
| 逐字校对层 | 人工按原音校正后的证据稿；默认保留语义性重复，环境声使用方括号标签 |
| 成稿层 | 面向阅读或出版的整理稿，可以合并、删减口头禅、重组段落和添加标题 |
| 字幕段 / Segment | 带稳定 ID、起止时间、文本和状态的最小校对单元 |
| 来源范围 / Source Range | 文件 ID + 开始时间 + 结束时间，用于把文字映射回原音 |
| 有效语音区间 | 由语音活动检测发现、并经人确认包含需要转写内容的时间范围 |
| 覆盖缺口 | 有效语音区间中没有文字映射，或尚未被人工确认的部分 |
| 疑点 | 对某个字词、人物、数字、断句或时间范围无法立即确认的结构化任务 |
| 接受不可辨 | 经重复听取仍无法确定，并由用户明确签署保留“听不清”标记的状态 |
| 质量闸门 | 导出“最终版”前必须通过的一组自动检查和人工签署 |
| 非破坏性增强 | 只改变播放效果或缓存代理，不修改源音频 |
| 项目术语表 | 人名、地名、机构、课程术语及其别名、正确写法和证据的集合 |
| RPO | 崩溃时允许丢失的最大数据时间窗口 |

# 二、产品描述（做什么）

## 2.1 产品需求描述

### 2.1.1 核心产品原则

1. **原音优先**：AI、字幕、术语表都只能辅助，不能覆盖人的最终判断。
2. **不隐藏不确定性**：听不清必须成为可分派、可复核、可签署的问题，不能默默猜测。
3. **证据稿与成稿分离**：逐字准确和行文流畅是两个不同目标，分别编辑、相互映射。
4. **时间轴即证据链**：每次修改、疑点、成稿段落和导出都能回到来源时间范围。
5. **键盘优先、鼠标可用**：高频动作可连续操作，所有快捷键可查看和自定义。
6. **本地优先**：默认离线、源文件只读、不依赖云服务即可完成全流程。
7. **长任务可恢复**：自动保存、断点续做、版本快照和后台任务状态是基础能力。
8. **完成由标准决定**：文件名变成“final”不代表完成，质量闸门通过才代表完成。

### 2.1.2 V1.0 范围

| 范围内 | 范围外 |
| --- | --- |
| 本地项目与文件夹批量导入 | 在线音频录制 |
| MP3 + SRT 的自动配对和手工修正 | 完整数字音频工作站能力 |
| 长音频波形、精确跳转、循环、降速、增益、语音增强预设 | 对源音频做母带级修复 |
| 原始识别、逐字校对、成稿三层模型 | 自动生成“无需人审”的最终文稿 |
| 字幕改字、分段、合并、时间调整、说话人 | 影视字幕视觉排版 |
| 疑点队列、术语表、上下文搜索 | 公共术语市场 |
| VAD 覆盖候选与质量闸门 | 把 VAD 判断当作绝对真值 |
| Markdown、SRT、TXT、JSON 和项目快照导出 | 直接发布到第三方出版平台 |
| 当前书稿来源格式适配 | 自动决定全书观点与编辑立场 |

### 2.1.3 默认校对规范

逐字校对层：

- 修正识别错词、同音词、标点和明显断句。
- 保留改变语气或含义的重复、否定、自我修正。
- “嗯、啊”等无语义填充词是否保留由项目样式配置；默认保留在逐字层，成稿层删除。
- 掌声、笑声、音乐等用统一标签表示，如“[掌声]”。
- 数字先忠实记录听到的表达；成稿层再按风格统一。
- 无法判断时创建疑点；不得只凭“读起来顺”替换。

成稿层：

- 可删除纯课堂互动、口头禅和无意义重复。
- 可调整句序和段落，但不得新增来源中不存在的事实或观点。
- 事实性补充必须标记为“编辑注”，不能伪装为讲者原话。
- 每个段落至少绑定一个来源范围；跨文件段落可绑定多个范围。

**[待确认 C2]** 建议以“忠实校对稿 + 可读成稿”作为默认交付；若最终只要逐字稿，可关闭成稿模块，但这会改变 V1.0 范围和验收项。

### 2.2.2 听不清片段处理子流程

~~~mermaid
flowchart TD
    A[选中文字或时间范围] --> B[一键创建疑点]
    B --> C[自动扩展前后文并开启 A-B 循环]
    C --> D[尝试原音 / 降速 / 增益 / 语音增强]
    D --> E[查看相邻句、全局同词、术语表、候选写法]
~~~

## 2.3 全局说明

### 2.3.1 全局异常处理

| 异常场景 | 处理方式 | 用户提示 |
| --- | --- | --- |
| 源文件被移动或改名 | 项目标红但保留全部编辑；允许“重新定位文件”并校验哈希 | “找不到源音频。请选择其新位置，现有校稿不会丢失。” |
| 源文件内容变化 | 禁止静默替换；展示旧、新哈希和时长，要求作为新版本导入 | “文件内容已变化，不能继续沿用原时间轴。” |
| SRT 解析失败 | 显示行号与原因；允许以纯文本导入或跳过 | “第 418 行时间格式无效，请修复或选择降级导入。” |
| 音频解码失败 | 保留项目条目；支持重试、重新定位或转码代理 | “音频暂时无法解码，原文件未修改。” |
| 波形/VAD/增强失败 | 不阻塞原音播放与文本编辑；后台任务可重试 | “分析失败，可继续用原音校对。” |
| 磁盘空间不足 | 立即停止写缓存；优先保证数据库提交；提供清理缓存入口 | “空间不足，已暂停生成缓存；校稿已保存。” |
| 数据库写入失败 | 编辑器进入只读保护，保留内存草稿并提供另存恢复包 | “保存失败，请不要关闭应用；可导出紧急恢复包。” |
| 应用崩溃 | 重启后自动打开恢复页，展示最后持久化时间和未完成后台任务 | “已恢复到 14:32:05，最多可能缺少最后 5 秒输入。” |
| 导出目标已存在 | 默认生成带版本号的新文件；覆盖需二次确认 | “文件已存在。建议导出为 V003。” |
| 权限不足 | 不修改目标；允许改选目录 | “无法写入此目录，请选择有权限的位置。” |
| 可选云服务不可用 | 保留本地工作流；任务进入失败队列，不自动重传私密内容 | “外部服务不可用，本地校对不受影响。” |

### 2.3.5 全局数据与时间规则

- 内部时间统一存储为整数毫秒，界面和导出按格式转换，禁止浮点累计误差。
- 字幕段满足 0 ≤ start_ms < end_ms ≤ audio_duration_ms。
- 相邻段默认允许间隙，不允许重叠；若确有多人同时说话，可显式标记“允许重叠”。
- 所有对象使用不可变 UUID；合并、拆分后保留来源关系，不复用已删除 ID。
- 所有修改记录 UTC 时间和本地时区；界面按 Europe/Zurich 或用户设置显示。
- 文件哈希建议使用 SHA-256；大文件导入时后台计算，不阻塞首次播放。

# 三、功能需求（怎么做）

## 3.1 项目创建、导入与文件配对

### 3.1.1 描述

把一组本地音频、字幕和可选参考资料建立为可恢复的校稿项目，自动完成文件识别、配对、完整性检查和后台索引。

### 3.1.2 用户故事

- 作为项目负责人，我希望选择“环境画卷”目录后一次导入全部 MP3 和 SRT，以便不用逐一建文件。
- 作为主校对者，我希望系统能识别文件名中多余空格并正确配对，以便不会把音频和错误字幕对应起来。
- 作为项目负责人，我希望应用发现源文件被替换时立即提示，以便旧时间轴不会悄悄套到新录音上。

自动配对算法：

1. 分别扫描支持的音频和字幕扩展名。
2. 对不含扩展名的文件名做 Unicode NFKC 规范化。
3. 去除首尾空白，把任意连续空白折叠为一个半角空格。
4. 先按规范化名称完全相等匹配。
5. 只有唯一候选时才自动确认；出现一对多或多对一时禁止猜测，进入冲突列表。
6. 导入后保存实际源文件名；导出来源引用默认使用字幕原文件名，而非规范化名。

## 3.2 音频播放、波形与非破坏性增强

### 3.2.1 描述

提供面向听写的低延迟播放能力：以“当前选中字幕段”为默认播放边界，支持精确跳转、段尾自动暂停、暂停回退、变速不变调、A-B 循环、波形缩放、音量增益和语音增强，并保证所有处理不改变源音频。普通播放不得自动串入相邻字幕段。

### 3.2.2 用户故事

- 作为主校对者，我希望暂停后再次播放时自动回退 1.5 秒，以便快速接回上下文。
- 作为主校对者，我希望每次播放只听当前要校对的一段，并在段尾自动暂停，以免下一段声音干扰当前文字判断。
- 作为主校对者，我希望点击字幕条目即可定位段首、点击行内“播放”即可从段首开听，以便右手用鼠标选段时无需再寻找播放头。
- 作为主校对者，我希望把听不清的 4 秒范围持续循环，并在原音和增强音之间切换，以便辨认模糊词。
- 作为主校对者，我希望以 0.75 倍速度播放但保持音高，以便听清快速讲话。
- 作为复核者，我希望点击疑点后立即听到疑点前 2 秒至后 2 秒，以便不用手工找位置。

### 3.2.3 前置条件

| 类型 | 条件 |
| --- | --- |
| 数据 | 媒体已成功导入且源文件可访问 |
| 功能 | 原音播放不依赖波形、VAD 或增强任务完成 |
| 权限 | 用户有读取源音频权限 |

### 3.2.4 后置条件

- 播放位置实时写入会话状态，并至少每 5 秒持久化。
- 当前选中段作为普通播放的有效范围；段尾暂停后保留该段为当前工作段。
- 用户的速度、增益、增强预设和自动回退设置按项目/用户保存。
- 循环范围可临时使用，也可随疑点持久化。
- 播放本身不改变任何校对状态；只有显式确认才算人工审核。

### 3.2.5 界面及交互

#### 单段播放状态规则

| 触发动作 | 播放前处理 | 是否自动播放 | 段尾行为 |
| --- | --- | --- | --- |
| 点击字幕条目的非操作区域 | 若正在播放先暂停；选中被点击段；精确定位到 `start_ms` | 否 | 不适用 |
| 聚焦某条校对文本框 | 与点击该字幕条目相同；重复聚焦当前条目不应造成播放 | 否 | 不适用 |
| 点击行内“▶ 播放” | 选中该段；无论此前播放头位于何处，都先定位到该段 `start_ms` | 是 | 普通模式在 `end_ms` 自动暂停 |
| 点击底部播放按钮或执行现有播放命令 | 若播放头位于当前段内则从当前位置恢复，并按设置自动回退但不早于段首；若已到段尾或位于段外，则从段首开始 | 是 | 普通模式在 `end_ms` 自动暂停 |
| 播放时点击另一字幕条目 | 先暂停旧段，再切换选中段并定位新段 `start_ms` | 否 | 不允许旧段继续出声 |
| 开启当前段循环 | 保持当前段为播放范围 | 不改变当前播放/暂停状态 | 播放到 `end_ms` 后回到 `start_ms` 并继续；这是唯一自动回绕模式 |

边界约束：

- 普通播放的可听范围为闭开区间 `[start_ms, end_ms)`；检测到播放头达到或越过 `end_ms` 时，立即暂停并把界面位置稳定在段尾。
- 由于浏览器音频事件按帧调度，段尾动作允许不超过 100 ms 的实现误差，但误差期间不得可辨识地播放下一段内容。
- 行内“播放”始终从段首开始；它不是“从上次暂停处继续”。继续播放只由底部播放按钮或现有播放命令承担。
- 普通播放过程中，后退、前进和自动回退都必须钳制在当前段内。
- 循环开关关闭后，下一次到达段尾恢复普通暂停规则。

增强预设的产品定义：

| 预设 | 目标 | 处理原则 |
| --- | --- | --- |
| 原音 | 保留原始听感 | 不做处理，只应用用户音量 |
| 语音清晰 | 提升讲话频段与响度一致性 | 温和高通、低通、压缩与响度归一；参数由音频预研确定 |
| 强降噪 | 稳定底噪明显的片段 | 降噪后限制增益，提示可能损失辅音 |
| 自定义 | 面向高级用户 | 可调降噪强度、语音频段、压缩和增益 |

约束：

- 所有增强输出均为可重建缓存，不写回源文件。
- 首次播放必须优先使用原音，不能等待增强代理。
- 增强算法不得生成或补写语音；界面明确写“辅助听辨，不代表原音事实”。
- 用户在增强模式下确认片段时，审计记录保存所用预设，便于复核。

| 场景 | 触发条件 | 处理方式 | 提示 |
| --- | --- | --- | --- |

## 3.3 逐字校对与时间轴编辑

### 3.3.1 描述

在原始识别层只读对照的基础上，按时间轴编辑逐字校对层，支持改字、断句、说话人、拆分、合并和确认，并维持稳定来源关系。

### 3.3.2 用户故事

- 作为主校对者，我希望当前字幕随播放高亮，并能直接输入修正，以便视线不离开正文。
- 作为主校对者，我希望按 Ctrl + Enter 确认当前段并自动进入下一段，以便连续处理。
- 作为主校对者，我希望把被机器截断的一句话合并，同时保留原始两个 cue 的映射，以便修正断句但不丢证据。
- 作为复核者，我希望看到原始识别与校对稿的差异，以便了解人工改了什么。

### 3.3.3 前置条件

| 类型 | 条件 |
| --- | --- |
| 数据 | 音频已导入；字幕可为空 |
| 权限 | 当前动作身份具有校对权限 |
| 状态 | 源文件未发生未确认的内容变化 |

### 3.3.4 后置条件

- 每次编辑自动保存并产生可撤销操作。
- 被修改的已确认片段自动回到“校对中”。
- 受影响的疑点、成稿来源和质量规则被增量重算。
- 当前片段确认时记录确认时间、动作身份、播放预设和文本版本。

#### 选中与播放规则

- 点击字幕段非操作区域：若旧段正在播放则先暂停；选中被点击段并把播放头精确移到其 `start_ms`，不自动播放。
- 聚焦某段校对文本框：执行与点击该字幕条目相同的选中和定位规则，不因获得编辑焦点而自动播放。
- 行内原“▶ 定位”按钮改为“▶ 播放”：点击后选中该段、精确定位到 `start_ms` 并立即播放；每次点击都从段首重新开始。
- 双击时间码：等价于点击该段行内“▶ 播放”。
- 普通播放只播放当前选中段，到 `end_ms` 自动暂停；不得默认继续下一段。
- 播放进入当前段时可同步高亮，但不得抢走校对文本框的输入焦点。
- Ctrl + Enter：保存并确认当前段，选择下一未校对段并精确定位其 `start_ms`，不自动播放。

#### 拆分

- 默认以光标位置拆文字，以当前播放位置拆时间。
- 若播放位置不在该段内，使用段时间中点并要求确认。
- 新段继承说话人、段类型和来源映射；两个新段状态均为“校对中”。
- 原段进入历史，不物理删除；相关疑点按文字锚点和时间范围重新归属。

#### 合并

- 仅可合并同一文件中相邻段。
- 新范围取最早开始至最晚结束；文本以可配置分隔符合并，默认无空格。
- 说话人不同时要求选择保留、标记多人或取消。
- 任一原段有未解决疑点时，疑点保留并迁移。

#### 时间轴吸附

- 拖动边界默认吸附到 10 ms。
- 可吸附到相邻段边界、播放头和波形局部静音点。
- 按 Alt 暂时关闭吸附。
- 不允许用一次批量操作默默截断文字；批量偏移前展示影响预览。

## 3.4 疑点、上下文与术语表

### 3.4.1 描述

把“听不清、拿不准、需要查证”从临时记忆变成结构化任务。疑点可锚定文字范围与音频范围，自动带上上下文、候选写法、已尝试方法和处理结论；术语表帮助跨文件保持专名一致。

### 3.4.2 用户故事

- 作为主校对者，我希望用一个快捷键把当前词和音频范围加入疑点队列，以便不中断主流程。
- 作为复核者，我希望打开疑点就自动循环其前后文，并看到其他文件中的相似用词，以便更快做判断。
- 作为成稿编辑者，我希望专名有统一标准写法和别名，以便避免同一术语在 66 小时材料里出现多种写法。
- 作为项目负责人，我希望任何“听不清”都有明确结论和责任状态，以便最终版不存在被遗忘的占位符。

### 3.4.3 前置条件

| 类型 | 条件 |
| --- | --- |
| 数据 | 疑点必须关联至少一个媒体时间范围或一个文本对象 |
| 权限 | 校对者可创建和编辑；复核动作需切换为复核者身份 |
| 功能 | 全局检索索引可异步建立；索引未完成不阻塞创建疑点 |

### 3.4.4 后置条件

- 疑点进入队列并影响相关片段和文件状态。
- 阻塞级疑点未解决时，项目不能通过最终质量闸门。
- 解决疑点后写入最终文字、依据和审计事件，相关片段回到“校对中”并需重新确认。
- 接受不可辨时插入项目统一占位符并保存签署信息。

### 3.4.5 界面及交互

#### 创建疑点

若用户先选中文字，则文字锚点为选区，音频范围取关联字幕段；若没有选区，则以播放头为中心取前 2 秒、后 2 秒，用户可在波形中调整。

#### 疑点详情

固定展示：

- 疑点前后至少三个字幕段。
- 原始识别、当前校对文本及差异。
- 一键 A-B 循环、原音/增强切换和速度设置。
- 全项目相同词、同音候选和相邻高频词的搜索结果。
- 术语表命中、别名、证据链接及使用次数。
- 已尝试方法复选：原音、减速、增益、语音清晰、强降噪、查上下文、查术语、交叉文件。
- 操作：采用候选、直接填写、暂缓、接受不可辨、关闭为非问题。

#### 接受不可辨规则

**[待确认 C3]** 建议占位符统一为“[听不清 01:23:45.678]”，并要求至少勾选三种已尝试方法后才能签署。成稿层默认不直接展示时间，而以“[原音不清]”或编辑性删节处理；证据层永远保留精确时间。

接受不可辨不是“解决为确定文本”，其状态和统计必须单独展示。若后续得到更清晰音源，可重新开启。

## 3.5 成稿编辑与来源映射

### 3.5.1 描述

把已确认的逐字校对片段整理为可读书稿，同时维持段落到一个或多个原音范围的显式映射。成稿编辑不反向覆盖逐字稿。

### 3.5.2 用户故事

- 作为成稿编辑者，我希望把连续的已确认片段加入一个书稿段落，并在右侧改写，以便去除口语但保留证据。
- 作为复核者，我希望点击成稿段落即可依次播放其全部来源，以便检查是否改变原意。
- 作为项目负责人，我希望任何无来源的成稿文字被明确标记，以便避免模型或编辑无意添加事实。
- 作为现有书稿维护者，我希望导出“标题 + 章节 + 来源 + 正文”的 Markdown，以便进入当前流水线。

### 3.5.5 界面及交互

#### 双栏编辑

左栏是可筛选的已确认校对片段，右栏是章节化成稿。用户可：

1. 多选连续或非连续片段，点击“加入成稿”。
2. 选择新建段落、附加到当前段落或作为独立引用。
3. 在右栏编辑标题与正文；底部显示来源 chips。
4. 点击某个来源 chip，左栏定位并从该范围播放。
5. 拖动来源 chip 调整播放顺序，但不改变原时间。
6. 查看“成稿 ↔ 校对稿”语义差异提示；提示只辅助，不自动否决。

#### 来源范围压缩规则

- 同一文件中相邻且间隔不超过 500 ms 的来源可在展示层合并。

- 跨文件来源不能压缩为单一区间。
- 成稿删除一段文字不会自动删除来源；系统提示检查冗余来源。
- 添加与来源无明显对应的新陈述时，编辑器给出“可能无来源”警告，用户需删除、改为编辑注或补充来源。

## 3.6 语音覆盖、质量检查与完成闸门

### 3.6.1 描述

用音频时长、语音活动候选、字幕时间轴、人工状态、疑点和来源映射联合判断完成度，避免“字幕改到最后一行”但仍漏音、留疑或失去出处。

### 3.6.2 用户故事

- 作为项目负责人，我希望看到哪些有声区间还没有文字，以便发现机器漏转。
- 作为主校对者，我希望质量问题能直接跳到音频和对应段，而不是只给一份抽象报告。
- 作为项目负责人，我希望系统只有在所有阻塞项清零时才允许签署最终版，以便“完成”有一致标准。
- 作为复核者，我希望区分“未解决疑点”和“已接受不可辨”，以便不把诚实保留的问题误当遗漏。

### 3.6.3 前置条件

| 类型 | 条件 |
| --- | --- |
| 数据 | 音频媒体信息已读取 |
| 分析 | VAD 可异步运行；未完成时对应覆盖检查标为“未知”，不能视为通过 |
| 权限 | 所有人可运行检查；只有项目负责人可签署完成 |

### 3.6.4 后置条件

- 生成项目、文件和具体对象三级质量报告。
- 每个问题具有规则 ID、级别、位置、修复入口和状态。
- 质量闸门通过后产生不可变签署记录及所依据的项目版本。
- 签署后的任意内容修改立即使签署失效。

### 3.6.5 界面及交互

#### 覆盖时间轴

同一时间轴叠加四条轨：

1. 音频全长。
2. VAD 检出的语音候选。
3. 有校对文字映射的范围。
4. 已人工确认或接受不可辨的范围。

区间分类：

| 分类 | 条件 | 默认处理 |
| --- | --- | --- |
| 已覆盖 | 有效语音与已确认片段重叠达到阈值 | 通过 |
| 有声无字 | VAD 为语音，但没有任何语音片段覆盖 | 阻塞候选，必须试听 |
| 有字无声 | 有语音文本，但 VAD 未检测到语音 | 警告，可能是 VAD 漏检或时间轴偏移 |
| 未人工确认 | 有文字，但片段状态不是已确认/接受不可辨 | 阻塞 |
| 非语音 | 用户确认音乐、静音或环境声 | 不要求逐字文本，但需类型标签 |
| VAD 未完成 | 后台分析未结束或失败 | 状态未知，最终闸门不通过 |

VAD 只产生候选，不直接删除、添加或确认文字。对于“有声无字”，用户必须选择：

- 补建语音片段并校对；
- 标记为音乐；
- 标记为环境声；
- 标记为不需转写的无意义人声，并写备注；
- 判定为 VAD 误报。

## 3.8 自动保存、版本历史与崩溃恢复

### 3.8.1 描述

确保数周到数月的校稿不会因应用退出、误操作、磁盘问题或错误批量修改而丢失，并允许查看差异、建立里程碑和恢复历史版本。

### 3.8.2 用户故事

- 作为主校对者，我希望输入后无需手动保存，以便专注听写。
- 作为项目负责人，我希望批量替换前自动创建快照，以便发现错误后整体恢复。
- 作为成稿编辑者，我希望比较任意两个成稿版本，以便知道复核修改了什么。
- 作为用户，我希望应用崩溃后回到刚才的文件和位置，以便最大限度减少重复工作。

### 3.8.3 前置条件

| 类型 | 条件 |
| --- | --- |
| 存储 | 项目数据目录可写 |
| 数据库 | 支持事务和写前日志或同等级别持久性机制 |
| 配置 | 用户未显式进入只读快照模式 |

### 3.8.4 后置条件

- 普通编辑在停止输入 500 ms 后持久化，最长 5 秒强制提交。
- 每个逻辑操作生成审计事件；复杂操作原子提交。
- 高风险操作前创建自动快照。
- 重启后能恢复到最近持久化版本和工作位置。

### 3.8.5 界面及交互

保存状态固定显示在顶栏：

- “保存中…”：本地事务正在提交。
- “已保存 14:32:05”：所有编辑已持久化。
- “3 项等待保存”：磁盘暂时繁忙，内存队列尚未落盘。
- “保存失败”：红色常驻，编辑器进入保护策略。

| 功能 | 说明 |
| --- | --- |
| 自动快照 | 导入完成、批量替换、批量偏移、恢复版本、最终签署和导出前建立 |

| 导出恢复包 | 包含数据库、配置、清单和校验和；默认不复制大音频 |

保留策略建议：

- 审计事件长期保留。
- 自动快照保留最近 30 份，以及每天最后一份保留 90 天。
- 手动里程碑和最终签署快照不自动删除。
- 缓存不纳入备份，可通过源文件重建。

## 3.9 导出与现有书稿流水线衔接

### 3.9.1 描述

在质量预检通过后，把逐字校对稿、成稿、问题清单和项目证据导出为开放格式。默认永不覆盖源文件，并为现有“环境画卷”Markdown 流水线生成可直接审阅的来源格式。

### 3.9.2 用户故事

- 作为主校对者，我希望导出修正后的 SRT 并保留毫秒时间码，以便其他播放器仍可使用。
- 作为成稿编辑者，我希望导出 Markdown，每个小节都有标题、章节和来源范围，以便并入现有书稿。
- 作为项目负责人，我希望导出时附带质量报告、源哈希和版本号，以便知道这份“最终稿”基于什么。
- 作为用户，我希望导出失败时原有文件不被截断，以便避免损坏成果。

### 3.9.3 前置条件

| 类型 | 条件 |
| --- | --- |
| 数据 | 项目至少有逐字校对内容 |
| 质量 | 草稿导出可带水印；“最终版”必须有当前有效签署 |
| 存储 | 目标目录可写且有足够空间 |

### 3.9.4 后置条件

- 通过临时文件写入并原子改名，得到完整导出物。
- 写入 manifest，包含格式、项目版本、源哈希、质量摘要和文件校验和。
- 建立导出记录和自动快照。
- 导出不会改变项目内容或源文件。

#### SRT 导出

- 序号按起始时间重新连续编号。
- 时间格式为 HH:MM:SS,mmm。
- 使用逐字校对文本；段类型为音乐/环境声时按项目设置输出标签或略过。
- 默认不输出说话人；可选“讲师：正文”前缀。
- 接受不可辨按项目占位符输出。
- 导出前检查非法重叠、空段和时间越界。

#### Markdown 成稿导出

“环境画卷”模板示例：

~~~markdown
## 品牌与产业分工的边界

**来源：** 青创 一 1 7月25日 上午9点10分.srt，01:00:01.100 - 01:05:07.280
~~~

规则：

- 每个小节使用二级标题。
- “章节”必须来自预设章节枚举或项目配置。

- 来源文件名使用导入时的 SRT 原文件名；只有无 SRT 时才使用音频文件名。
- 内部逗号时间格式统一转换为点号毫秒格式，以匹配现有 Markdown。
- 不直接写入 books/src/content；先导出到用户选择的 staging 目录，由用户审阅后并入。

# 五、附录（补充文档）

## 5.1 验收标准与测试要点

### 5.1.1 端到端验收场景

以真实文件“青创 一   1   7月25日 上午9点10分.mp3”及其单空格 SRT 为基准：

1. 新建项目并选择“books/transcripts/环境画卷”目录。
2. 系统识别 21 份 MP3 和 21 份 SRT，并在没有歧义的情况下全部正确配对。
3. 首个文件在全量波形/VAD 完成前可开始播放和编辑。
4. 用户点击任一字幕条目，应用暂停旧播放、选中该条并精确定位段首，但不自动播放。
5. 用户点击该条行内“▶ 播放”，应用从段首开始，只播放这一段并在段尾自动暂停；下一段没有被播放。
6. 用户定位至 00:20:08.780，修改跨段断句，建立一个专名疑点。
7. 用户用 0.8×、+6 dB、A-B 循环和语音清晰模式听辨，并记录处理结论。
8. 用户完成一个字幕段确认；重启应用后，文本、状态、播放位置和设置全部恢复。
9. 用户把已确认来源加入成稿，编辑为书面段落，并一键回放来源。
10. 质量中心发现文件末尾音频与字幕末尾的差异，要求人工分类。
11. 所有阻塞项清零后签署完成，导出 SRT、Markdown、JSON 和质量报告。
12. SRT 可被应用重新导入且时间与文本一致；Markdown 来源格式符合现有书稿规范；源 MP3 和源 SRT 的哈希不变。

| AC-038 | 后台降级 | 波形、VAD 或增强失败时，原音播放和文本编辑仍可继续，失败可重试 | P0 |
| AC-039 | 大列表性能 | 加载 500,000 个模拟段时使用虚拟列表，不产生与总段数线性对应的 DOM 节点 | P0 |
| AC-040 | 诊断脱敏 | 导出的默认诊断包不含正文、完整路径、音频或 API 密钥 | P0 |
| AC-041 | 点击条目定位 | 正在播放 A 段时点击 B 段非操作区域或聚焦 B 段文本框，A 立即暂停，B 被选中，播放头定位到 B 的 `start_ms`（误差 ≤ 100 ms），且 B 不自动播放 | P0 |
| AC-042 | 行内播放 | 无论播放头此前位于何处，点击 B 段行内“▶ 播放”后都选中 B、从 B 的 `start_ms` 开始播放；按钮文案和可访问名称均为“播放”而非“定位” | P0 |
| AC-043 | 单段播放边界 | 普通模式播放任一段 20 次，每次均在该段 `end_ms` 后 100 ms 内暂停，跨段可辨识误播为 0；再次播放从该段段首开始；开启循环后则在段尾回段首继续 | P0 |

### 5.1.3 文稿质量抽检

自动规则不能替代人工内容质量。最终签署前按文件执行抽检：

| 抽检层级 | 建议抽样 | 检查内容 | 不通过处理 |
| --- | --- | --- | --- |
| 逐字稿 | 每文件随机 3 段，每段 60 秒；另抽所有接受不可辨 | 漏字、错词、否定、数字、专名、时间范围 | 发现严重错误则扩大抽样；达到阈值时退回整文件 |
| 成稿 | 每章节至少 3 段，含跨来源段落 | 是否改变原意、是否新增事实、来源是否完整 | 段落退回；系统性问题退回章节 |
| 覆盖 | 每文件开头、末尾和 3 个 VAD 边界 | 是否把讲话误标为非语音 | 补建文字并重跑检查 |
| 导出 | 每种格式至少打开并回读一次 | 编码、时间、标题、来源、特殊字符 | 修复导出器后重新生成 |

严重内容错误定义：改变否定、数量、主体、因果、专名或核心观点。抽检阈值 **[待确认 C7]**；建议任何严重错误即退回相关文件，普通错字率超过千分之一时扩大至双倍样本。

## 5.2 发布准入标准

V1.0 发布必须同时满足：

1. AC-001 至 AC-040 中所有 P0 用例通过。
2. 使用至少三份真实音频完成生产试用：一份清晰、一份一般、一份最困难。
3. 连续 4 小时工作会话无崩溃、无音文漂移、无无法恢复的保存错误。
4. 真实项目 SRT 导出往返误差为 0 ms。
5. 对当前 21 份音频执行覆盖检查，能明确显示“各文件音频总长减去最后一条字幕结束时间”的合计差异 00:07:08.606；不得把这段差异自动等同为语音。
6. 源文件在导入、编辑、质量检查和导出后哈希不变。
7. 隐私测试确认默认无项目内容出网。
8. 至少完成一次从旧版本项目数据库升级与回滚演练。
9. 阻塞级安全、数据丢失和导出损坏缺陷为 0。

## 5.5 设计决策记录

| 决策 | 选择 | 未选择方案 | 原因 |
| --- | --- | --- | --- |
| 产品形态 | 本地桌面应用 | 纯网页上传 | 文件总量大、路径和隐私要求高、需要稳定全局快捷键 |
| 文稿模型 | 原始识别 + 逐字校对 + 成稿三层 | 单文本直接改到底 | 准确性与可读性目标不同，单层会丢证据 |
| 完成判定 | 质量闸门 + 人工签署 | 用户手动标完成 | 可防止漏音、遗留疑点和失去来源 |
| 音频增强 | 非破坏性播放/缓存 | 覆盖源音频 | 原音必须保持事实来源 |
| 默认播放范围 | 当前选中字幕段 | 默认连续播放整份音频 | 人工校对以单段为工作单元；段尾硬暂停可避免声音越过文字边界，减少误校和重复定位 |
| 漏转检测 | VAD 候选 + 人工裁决 | 仅看字幕末尾 / VAD 自动定案 | 字幕会漏转，VAD 也会误报 |
| AI 使用 | 可选候选，不自动覆盖 | 全自动润色并发布 | 用户明确要求人工校对，准确性优先 |
| 仓库衔接 | staging 导出 | 直接修改正式书稿 | 降低误覆盖与错误批量合并风险 |

## 5.6 交接摘要

1. V1.0 是本地优先的长音频校稿桌面工具，核心不是重新转写，而是让人工校对可操作、可恢复、可验收。
2. 数据模型必须分为只读原始识别、逐字校对和成稿三层，并以毫秒时间范围互相映射。
3. P0 主链路为：批量配对 → 播放增强 → 逐段确认 → 疑点复核 → 成稿映射 → 覆盖 QA → 签署 → 导出。
4. 真实验收规模为 21 份音频、66:08:49.916、约 1.77 GiB、24,671 个 SRT cue。
5. 质量中心必须处理音频与字幕末尾合计 00:07:08.606 的差异，并用 VAD + 人工裁决查找其他潜在漏转。
6. V0.1 先以一份 3 小时以上真实文件做纵向样机；V0.5 用三份不同难度音频试产；V1.0 才跑全量。
7. 开发启动前优先确认 C2（成稿范围）、C3/C4（不可辨政策）、C6（平台顺序）。
